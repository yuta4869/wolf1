# GitHub PR workflow and attribution policy

This document operationalizes the policies declared in `CLAUDE.md`:

- `## GitHub PR workflow`
- `## No AI attribution policy`

The intent is to move enforcement from "we trust everyone to read CLAUDE.md"
to "the build fails if someone forgets". This PR introduces the first piece:
a shell script that scans for forbidden attribution markers in commit
messages, staged files, arbitrary files, inline text, and git identity.

## Branch and PR procedure

For every implementation PR from #8 onward:

1. Start clean: `git checkout main && git pull --ff-only origin main`.
2. Branch: `git checkout -b pr-<number>-<short-topic>` (kebab-case).
3. Implement the change.
4. Run the full test suite on the host:
   `PYTHONPATH=src python3 -m unittest discover -s tests -t . -v`.
5. Run the full test suite in Docker:
   `docker compose run --rm wolf`.
6. Only when both pass, run the attribution guard against staged content:
   `scripts/check-no-ai-attribution.sh --staged`.
7. Commit with a `PR #<n>: <imperative subject>` message.
8. Run the guard against the commit:
   `scripts/check-no-ai-attribution.sh --commit HEAD`.
9. Push: `git push -u origin pr-<number>-<topic>`.
10. Create the PR via `gh pr create` (if available) or the compare URL
    `https://github.com/<owner>/<repo>/compare/main...pr-<number>-<topic>`.
11. PR body must follow the format in `CLAUDE.md ## Reporting style`:
    Summary, Files changed, Commands run, Verification, Security / safety
    posture, Risks / limitations, Next recommended step.

Direct push to `main` is forbidden. The one exception was PR #7, which was
committed to `main` before this workflow existed; it will not happen again.

## What the attribution guard catches

`scripts/check-no-ai-attribution.sh` rejects fixed strings such as:

- `Co-Authored-By: Claude` (and lowercase variants)
- `Generated with Claude` / `Generated by Claude`
- `Created by Claude` / `Authored by Claude`
- `Claude Code generated`
- The U+1F916 robot emoji followed by `Generated`

It also rejects git identity values whose name or email contains `claude`
or `anthropic` (case-insensitive). The list lives in
`scripts/check-no-ai-attribution.sh` and can be extended without changing
the calling code.

## Allowlist

Some files legitimately need to mention the forbidden strings to describe
the policy. The guard exempts them when scanned via `--file`:

- `CLAUDE.md`
- `docs/dev/pr_workflow.md`
- `scripts/check-no-ai-attribution.sh`
- `tests/test_no_ai_attribution.py`

The allowlist applies to `--file` and `--staged` modes. It does NOT apply
to `--commit`, `--text`, or `--identity` — those modes are absolute.

## Invoking the guard

```sh
# Check the most recent commit (message + author + committer identity).
scripts/check-no-ai-attribution.sh --commit HEAD

# Check all staged files before committing.
scripts/check-no-ai-attribution.sh --staged

# Check a single file (e.g. a PR body draft).
scripts/check-no-ai-attribution.sh --file /tmp/wolf-pr-9.md

# Check an inline string.
scripts/check-no-ai-attribution.sh --text "$(cat /tmp/draft.md)"

# Check the current git identity (catches AI / bot author misconfig).
scripts/check-no-ai-attribution.sh --identity
```

Exit codes:

- `0` — no forbidden marker found
- `1` — usage / internal error (bad ref, missing file, etc.)
- `2` — forbidden marker found; output identifies which marker and where

## What this does NOT enforce

- Subtle paraphrases that mean the same thing without using the literal
  strings. The guard is a substring check, not an LLM-based classifier.
- Attribution stored in commit GPG signatures, tags, or git notes.
- Identity drift after the commit: if the guard passes at commit time
  but the user later rewrites history, the rewrite has to be re-scanned.
- Code that is *generated by* an AI but contains no attribution string.
  Authorship is a separate concern from attribution markers.

The guard is a tripwire, not a proof of human authorship.

## Future hardening (out of scope for PR #9)

- A `pre-commit` hook calling `scripts/check-no-ai-attribution.sh --staged`
  and `--commit HEAD` on the local machine.
- A GitHub Actions workflow running the guard against the PR head ref and
  the PR body via `gh api`.
- A regex extension to catch `🤖 (generated|wrote|made)` etc. once we see
  paraphrases in the wild.
